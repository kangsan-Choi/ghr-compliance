Global ER 점검 Agent

해외법인 ER(Employee Relations) Risk를 사전 진단하고 HR 제도 개선을 제안하여, 법인의 노무 Risk를 최소화하는 웹 기반 점검 도구입니다.

▶ 실제 데모 보기 전체 구조 살펴보기

1. 과제 개요 Overview

"법을 몰라서 생기는 리스크"를 담당자가 클릭 몇 번으로 미리 잡아낼 수 있게 합니다.

🎯

목적

해외법인 ER Risk 사전 진단 및 HR 제도 개선 제안을 통한 법인 노무 Risk 최소화.

👥

사용자

본사 글로벌 HR 담당자 및 각 해외법인 ER/HR 담당자. 비개발자도 링크 접속만으로 사용.

🧭

해결하는 문제

국가별로 다른 노동법·개정사항·사업장 규모별 의무를 일일이 추적하기 어려운 현실을 자동 점검으로 대체.

한 줄 요약 — 국가·도시별 노동법 기준값과 우리 회사 HR 제도(직원 수 포함)를 비교해 🔴위반 / 🟡주의 / 🟢적합 / 🔎수동확인으로 자동 판정하고, 개선 권고와 최종 리포트(HTML)를 제공합니다.

이 프로젝트는 ① 데이터를 만드는 단계와 ② 사용자에게 서비스하는 단계가 분리되어 있습니다.

"rules.py를 서버처럼 저장해 꺼내 쓰는가?" — 정확히는, 별도의 데이터베이스/서버는 없습니다. rules.py는 앱이 불러오는 판정 로직 모듈, data/*.json은 사전 수집한 법령 백데이터이며, Streamlit Cloud가 GitHub 저장소를 통째로 가져와 실행하는 구조입니다.

3. AI 에이전트 구성 Multi-Agent Pipeline

초기 HTML 도구와 법령 데이터를 만들기 위해 설계한 7개 에이전트입니다. 실제로 작동하며, 개발(데이터 갱신) 단계에서 호출됩니다.

에이전트역할작동 위치/시점
compliance-orchestrator
(오케스트레이터)		 전체 파이프라인을 정해진 순서로 지휘하고, 하위 에이전트 결과를 모아 대시보드/리포트를 생성 Claude Code 내부
(개발·데이터 구축 시점)
labor-law-researcher 국가별 최신 노동법·개정사항·최저임금·근로시간 등을 웹에서 조사하고 출처와 함께 정리
hr-policy-structurer 회사 HR 제도(근로시간·휴가·급여·해고·복리후생)를 표준 JSON으로 구조화 (개인정보는 제외)
compliance-gap-analyzer 법정 기준 vs 현행 제도를 항목별 비교해 🔴긴급/🟡권고/🟢준수로 갭을 판정
gap-analysis-reporter 갭 분석 결과를 경영진용 구조화 리포트(요약·긴급·권고·참고)로 작성
law-amendment-monitor 법령 스냅샷을 비교해 최근 3개월 내 개정을 감지하고 재분석을 촉발 ("새로고침")
중요 구분 — 이 에이전트들은 "데이터를 만드는 도구"입니다. 완성된 웹앱은 이들이 만든 결과(data/*.json)를 꺼내 쓰기만 하며, 사용자가 앱을 쓸 때 에이전트가 매번 돌지는 않습니다. 덕분에 빠르고 안정적이며, 법령이 바뀌면 개발 단계에서 에이전트로 데이터만 갱신해 다시 배포합니다.

4. 현재 웹앱 작동 방식 How the App Works

사용자가 보는 화면 뒤에서 무슨 일이 일어나는지의 흐름입니다.

국가·도시 선택 → 해당 data/*.json의 법정 기준(근로시간·연차·최저임금·해고예고 등)과 개정 타임라인을 불러옵니다.
사업장 직원 수 입력 → 직원 수에 따라 달라지는 규제(예: 취업규칙·고충처리·여성위원회 등)의 적용 여부를 자동 판정합니다.
우리 회사 제도 입력 → 정규/최대 근로시간, 연차, 해고예고, 임금 등 실제 값을 입력(기본값은 법정 기준).
일괄 Risk 분석 → rules.py가 법정 기준과 입력값을 비교해 🔴/🟡/🟢/🔎로 판정.
결과 + 리포트 → 종합 리스크 게이지와 항목별 권고를 보여주고, 최종 HTML 리포트를 내려받습니다(인쇄·PDF·필터 지원).

5. 개발 과정 Evolution

정적 HTML 도구에서 시작해, 데이터와 로직을 분리한 배포형 웹앱으로 발전했습니다.

1세대 · 국가별 정적 HTML 도구

국가마다 개별 HTML 파일로 점검 도구/리포트를 제작 (현재 archive_html_초기버전/에 보관). 직관적이지만 국가가 늘 때마다 파일이 늘고, 법령 갱신·관리가 번거로움.

2세대 · Python · Streamlit 통합 웹앱 현재

화면(compliance_app.py) · 로직(rules.py) · 데이터(data/)를 분리. 8개국을 하나의 앱에서 점검하고, 직원 수 규모별 규제·리스크 게이지·리포트 다운로드를 추가.

3세대 · 클라우드 배포 + 링크 공유 현재

GitHub에 저장 → Streamlit Community Cloud가 자동 배포. 해외 담당자가 설치 없이 링크로 접속. 수정은 "GitHub에 올리기(Push)"만 하면 자동 반영.

7. 추가 해결이 필요한 부분 Roadmap & Open Issues

현재 버전은 "사전 저장 데이터 + 룰 판정"에 최적화되어 있습니다. 다음은 솔직한 한계와 개선 방향입니다.

구분현재 한계개선 방향우선순위
법령 최신성 데이터가 특정 시점(2026-06) 기준으로 고정. 개정 시 수동 갱신 필요. law-amendment-monitor를 정기 실행해 변경 감지 → 데이터 자동 갱신·재배포 연계 높음
국가 커버리지 현재 8개국(도시 단위). 법인 소재 국가로 확대. 에이전트 파이프라인으로 국가 추가가 비교적 쉬움 높음
회사 데이터 저장 입력값이 세션 기반(새로고침 시 초기화), 법인별 이력 저장 없음. 법인별 프로필 저장/불러오기, 점검 이력 관리 기능 중간
주관식 자동화 주관식 질문은 프롬프트를 만들어 수동 복붙으로 LLM 질의. (보안 검토 후) LLM API 연동으로 앱 내 자동 답변 — 비밀키는 Secrets로 관리 중간
접근 제어 링크를 아는 사람은 접속 가능. 필요 시 뷰어 이메일 제한/사내 SSO 연계 낮음
법적 정확성 자동 판정은 참고용. 해석 여지가 있는 항목 존재. 현지 노무사/변호사 검수 절차 병행, 출처 링크 상시 노출(이미 일부 적용) 높음
